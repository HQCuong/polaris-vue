- **Подстраивайтесь под контейнер, а не под viewport.** Query-контейнер позволяет компонентам реагировать на ширину своего контейнера. Это помогает компонентам, которые встречаются в местах разной ширины, например карточке товара в боковой панели или в основной колонке.
- **Давайте контейнерам имена, если их несколько.** Если нескольким query-контейнерам нужны разные запросы, задайте каждому описательный `containerName`, чтобы обращаться к нему; безымянные контейнеры отвечают на одни и те же запросы.
- **Задавайте адаптивные значения в пропсах.** Контейнер предоставляет контекст, который компоненты Polaris используют для вычисления адаптивных значений пропсов, например `padding="@container (inline-size > 500px) large-500, none"`, так что CSS для container query писать самим не нужно.
- **Применяйте только там, где нужно.** Каждый query-контейнер заставляет браузер отслеживать его размер и применять условные стили, поэтому добавляйте его там, где нужна адаптивность по контейнеру, а не оборачивайте им каждый элемент.

```vue
<SQueryContainer>
  <SBox padding="@container (inline-size > 500px) large-500, none">
    <!-- … -->
  </SBox>
</SQueryContainer>
```

Полное руководство см. в [рекомендациях Shopify для `<s-query-container>`](https://shopify.dev/docs/api/app-home/latest/web-components/layout-and-structure/query-container#best-practices) (на английском).
