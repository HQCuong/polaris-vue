# Homepage redesign: Apple-style hero on a glowing grid

Date: 2026-10-30. Status: content approved in conversation. Waiting for the owner to sign off this document.

## Intent

The owner wants the docs homepage (https://polaris-vue-elements.dev/) to feel
**premium and high-tech**. The tools for that are light animation, a soft gradient
background, and a layout in the style of Apple product pages: centered, large type,
generous whitespace, restrained motion.

The homepage is also the site's main SEO entry point. The owner set a hard rule:
**nothing in this redesign may hurt SEO.**

The redesign also adds one message. Built for Shopify, the diamond-badge program,
reviews apps on whether they look and feel like the Shopify admin. Polaris web
components *are* the admin's UI, and this library brings them to Vue.

## Goals

- A new hero ("D + B" in the mockups), described below.
- The three sections below the hero are restyled to match: features, intro with
  code, and the all-components list.
- Light and dark mode both look intentional.
- Every animation is CSS-only and turns off under `prefers-reduced-motion: reduce`.

## Non-goals

- No changes to any page other than the homepage, except shared tokens that already
  apply site-wide. The existing brand green (`--vp-c-brand-*`) stays.
- No new runtime dependencies (no animation libraries, no web fonts).
- No changes to the title, meta description, canonical, Open Graph, JSON-LD, the
  sitemap, or URLs.

## Anti-goals (a failure even if it looks good)

- Any SEO regression:
  - homepage text or links that disappear from the server-rendered HTML;
  - a second `<h1>`, or no `<h1>`;
  - existing `<h2>` headings that get removed or renamed;
  - the LCP element (the hero headline) hidden at load with `opacity: 0`, or
    revealed by JS;
  - layout shift (CLS) when animations start or fonts load.
- Implying that the library is certified by Shopify or makes an app Built for
  Shopify. Do **not** use Shopify's Built for Shopify badge artwork or logo.
- Motion that is busy, fast or attention-grabbing. Loops run on slow cycles
  (6–8s or longer).
- Breaking the Polaris CDN script, the local search, or the nav/sidebar on mobile.

## Constraints

- VitePress 1.6.4, default theme (`docs/.vitepress/theme/index.ts` re-exports
  `DefaultTheme`), with overrides in `docs/.vitepress/theme/custom.css`. The
  existing comment style in that file explains *why* each override exists; match it.
- The homepage is `docs/index.md` (`layout: home`, with `hero` and `features`
  frontmatter, then markdown sections). `transformPageData` in
  `docs/.vitepress/config.ts` builds the title and JSON-LD from the frontmatter.
  The homepage title is `${pageData.title} | ${SITE_NAME}`, from frontmatter
  `title`, **not** from the hero. Keep the frontmatter `title` and `description`
  unchanged.
- The all-components list renders from `docs/.vitepress/components-sidebar.json`,
  which is generated by `scripts/generate-docs.mjs`. Do not hand-edit that file.
  Current groups and counts (62 total):
  - Actions 7
  - Feedback and status 5
  - Forms 20
  - Layout and structure 18
  - Media and visuals 4
  - Overlays 2
  - Typography and content 6

  Counts shown on the page must be computed from the JSON, not hard-coded.
- The site works at phone width (no horizontal scroll) and in both color modes.
  VitePress toggles `.dark` on `<html>`.
- Existing checks must pass: `npm run check`, `npx vitest run`, `npm run docs:build`,
  and the CI freshness check (`npm run generate && npm run docs:generate && git diff
  --exit-code`).
- Project rule: verify visual and behavioral claims in a real browser, light and
  dark, desktop and phone width.

## The design (decided with the owner)

### Hero

- **Layout:** centered, Apple product-page style. Order, top to bottom:
  1. Eyebrow pill (see below).
  2. Headline, the page's only `<h1>`, on two lines: **"Shopify Polaris."** /
     **"Now typed for Vue 3."** The second line uses the brand-green gradient text,
     with a slow sheen that sweeps across it (about 6s loop).
  3. Tagline: the current one, unchanged ("Typed Vue 3 components around Shopify's
     Polaris web components (s-button, s-text-field, s-modal, ...) — no separate
     Vue-specific design system to learn.").
  4. Two actions: **Get Started** → `/guide/getting-started` (filled green pill)
     and **Components ›** → `/components/` (text link style).
  5. A floating code card with a frosted-glass look (translucent white, backdrop
     blur, soft green-tinted shadow, gentle vertical float on about a 6s loop). It
     shows:
     ```vue
     <STextField v-model="name" />
     <SButton variant="primary">Save</SButton>
     ```
     with syntax colors.
- **Background:** near-white (`#fbfcfc` range). A thin grid in brand green at about
  9% alpha, 22px cells, masked by a radial gradient so it fades out from the
  center. A large soft green radial glow rises from the bottom center and slowly
  "breathes" (scale and opacity, about 8s).
- **Dark mode:** same structure on the site's dark background. The grid and glow
  use the mint brand tones already defined under `.dark` in custom.css, and the
  glass card becomes dark translucent.
- **Eyebrow pill:**
  - A rounded pill with a light green tint and a hairline green border.
  - It contains a **self-drawn outline diamond icon** (inline SVG, *not* Shopify's
    badge) and the text **"The Built for Shopify look. *Out of the box.*"**. The
    second sentence is emphasized in brand green, followed by a `›`.
  - The whole pill links to
    https://shopify.dev/docs/apps/launch/built-for-shopify/requirements and opens in
    a new tab with `rel="noopener"`.
  - A soft highlight sweeps across the pill every few seconds.
- **Load animation:**
  - The eyebrow, tagline, actions and code card rise into place, staggered.
  - The `<h1>` must be visible from the first paint. Allowed: a transform-only rise
    or no animation. Not allowed: `opacity: 0` → 1.
  - Secondary elements may fade, but must not shift layout: their space is
    reserved from the start.
- **Brand name:** "polaris-vue-elements" no longer appears in the hero. It stays in
  the nav bar title, `<title>`, JSON-LD and Open Graph. That was the owner's choice.
- **H1 change, approved by the owner as an SEO trade-off:**
  - The old hero `<h1>` ("polaris-vue-elements Vue 3 wrappers for Shopify Polaris")
    is replaced by the new headline. The SEO before/after diff treats the old
    `<h1>` strings as **expected removals**.
  - The phrase **"Vue 3 wrappers for Shopify Polaris"** must stay **visible** on the
    page, as the small kicker line above the features grid (replacing the mockup's
    "Why polaris-vue-elements").
  - Never use visually hidden text to keep old keywords; Google treats that as
    hidden text.
  - Update the `hero` frontmatter in `docs/index.md` to match the new hero, or remove
    whatever the custom hero no longer reads, so no stale values mislead future
    editors.

### Features section (below the hero)

- The four existing features, with **title and details text unchanged**, laid out
  as a bento grid of rounded white tiles with hairline borders. Tiles differ in
  size: two wide tiles and two narrow ones on desktop, a single column on phones.
- Tiles may carry a large gradient number: "62" for typed props and events, and
  "17" for v-model. Compute 62 from the components JSON. 17 already appears in the
  existing copy and comes from overrides, so it can stay as copy.
- The v-model tile may show a tiny code snippet, e.g. `<SSwitch v-model="on" />`.
- VitePress 1.6 renders each feature title as an `<h2>`. Keep those four titles as
  `<h2>` in the bento tiles, so the page's `<h2>` set stays the same. (My call,
  following the "existing `<h2>`s unchanged" rule.)
- Hover: lift a few px with a soft green shadow, as the current `.VPFeature` hover
  does.
- Above the grid, a **required** centered kicker reads "Vue 3 wrappers for Shopify
  Polaris" (see the H1 note above). Below it there may be an optional Apple-style
  line, e.g. "Everything Polaris. Nothing to relearn." That line is decorative text,
  not a heading that replaces anything.

### Intro and code section

- **Keep the existing `<h2>` "Polaris web components, typed for Vue"** and the
  existing paragraph text and links verbatim.
- Two-column layout on desktop: text on the left, the existing code example on the
  right inside a macOS-style window card (three dots, rounded corners, soft
  shadow). It stacks on phones.
- The code block must still be the normal VitePress code block, so syntax
  highlighting and the copy button keep working, only framed differently.

### All components section

- **Keep the existing `<h2>` "All components"** and every component link (all 62,
  as real `<a href>` in the server-rendered HTML).
- Each sidebar group becomes a rounded card: the group name with its count (from
  the JSON) on the right, and components as pill chips. Chip hover uses a brand
  tint. The grid is 2 columns on desktop and 1 on phones.
- An optional Apple-style line under the heading: "62 components. One import."
  (number computed).

### Motion and accessibility

- All motion is CSS keyframes and transitions, with no JS animation loop.
  Scroll-reveal of the sections, if added, may use a tiny `IntersectionObserver`
  that only adds a class. Content must be fully visible without JS.
- `@media (prefers-reduced-motion: reduce)` disables every animation and
  transition added here.
- Text contrast meets WCAG AA in both modes, including the gradient text and the
  pill. The current hero gradient ends at `#4fb8a0`, which falls below 3:1 on
  near-white. The "Now typed for Vue 3." gradient therefore uses darker greens in
  light mode. (My call.)

## Left to the builder

- Implementation approach:
  - Override the hero through VitePress's home layout slots, or a custom
    `HomeHero` component registered in `theme/index.ts`.
  - Or style the default hero and render the extra pieces (pill, code card) via
    layout slots.
  - The new homepage sections can be Vue components used from `index.md`.
  - Choose whatever keeps the HTML semantic and the diff maintainable. Moving
    `hero`/`features` frontmatter content into components is fine as long as the
    rendered text is identical.
- Exact sizes, spacing, easing curves and colors within the brand palette.
- Whether to add the optional decorative lines.
- How to verify no SEO regression. At minimum:
  - diff the text content and `<a href>` set of the built `index.html` before and
    after;
  - check that there is exactly one `<h1>` and that the `<h2>`s are unchanged;
  - run a Lighthouse pass, or check LCP and CLS, on the built site.
